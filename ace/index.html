The Atomic Constraint Engine

One primitive. Done is derived, never stored.

ACE runs construction work on one kind of record, the atom. A permit, a delivery, an RFI (request for information), an inspection and a whole work area are all atoms, joined by two links: requires, what must finish first, and contains, its children.

No atom has a done field. People record what they did: closed it, signed it, wrote it up. Done is worked out from those facts and the graph each time anyone asks, so there is nothing to keep up to date.

Tap through a job Meet the atom

ACE is written in Sprout, this site's own programming language. Each idea below is a short Sprout program, running on this page.

If you run the work

The schedule, the constraint log, the RFI list, the inspection register and the area rollups all describe the same job. In ACE they are one graph. Close what you finished, and the graph tells you what is done, what can start today, what each piece of work is waiting for, and which chain of work sets the finish. There is no percent-complete column to keep up to date.

If you write the code

An atom is a record and the two links are edges. Done is a fixed point: start from the empty set, add every atom whose rule holds, and repeat until a pass adds nothing. Everything else is a function of the graph. The critical path is a walk, the forecast is a Monte Carlo run over that walk, and the morning ranking is the difference between two sets of workable atoms. Each is a few dozen lines of Sprout.

The primitive

The atom

Everything on the job is the same kind of record. This one is from ace-derive.sp, written one field to a line.

[
id : "place-rebar"The name its links use.
name : "Place rebar"What people call it.
kind : "leaf"Who says it is done: one of five kinds.
closed : falseA fact someone recorded. Done is worked out from facts like this one.
tags : []Free labels. Only one carries a rule: narrative-required.
requires : ["dig", "rebar-on-site", "rfi-splice"]What must finish first.
contains : []Its children. A work area contains the work in it.
]
  • trivialBorn done: a fact other atoms can rely on, such as an issued design basis.
  • leafA person closes it.
  • verifiedClosed and signed by a witness: two locks. Permits and inspections.
  • gateDone when everything it requires is done. RFIs and constraints.
  • rollupDone when all its children are done. Areas and work packages.

A tag carries no rule, with one exception: narrative-required. An atom with it is not done, however it was closed, until someone writes down what happened.

01ace-derive.sp

Done is a fixed point

Each kind of atom has one rule for when it closes. To find out what is done, ACE starts from nothing and closes every atom whose rule holds. Then it goes round again with what it just learned, until a pass closes nothing new. That resting point is the answer, and it is worked out afresh every time anyone asks.

This program prints four snapshots of the pedestal: today; after the rebar arrives and the RFI is answered; after the inspection is signed but not yet written up; and after the write-up.

02ace-board.sp

Tap the work, and the graph does the rest

The same idea with a finger on it. A leaf closes with one tap. A verified atom takes two, the work and then the witness. Gates and the rollup are never tapped: they close themselves when what they wait on is done. Blocked work refuses the tap and says what it waits on.

Red marks the critical path, the chain of open work that sets the finish. The inspection has to be written up, and the write-up is structure: choose rework or NCR (non-conformance report) and new atoms join the graph, with the pour waiting for them.

03ace-crews.sp

Sequence and capacity, one link

Work waits for two kinds of thing. A sequence constraint points at an atom: the pour requires the rebar. A capacity constraint points at a query: any idle crew of the right trade. Both say that this can't start until that is true, so ACE holds them in the same link.

Each day, every free crew takes the first ready work of its trade. There is one iron crew. Send it home before the rebar starts and the rebar waits, and so does everything behind it: the embeds, the pour, the columns.

04ace-schedule.sp

The plan is a distribution, not a date

The critical path is a walk: start at the last atom and step back through whichever requirement finishes last. Give every duration three numbers, fastest, likely and slowest, add one shared risk, wet weather on the pour, and run the job 400 times. The finish becomes a spread.

On likely durations the job finishes on day 21. Across the runs it makes day 21 only 2% of the time, and P80, the day by which 80 runs in 100 have finished, is day 28. Cost is a view of the same graph: crews times rates times days, plus materials, and earned value on a status day.

05ace-risk.sp

A million runs, and what each risk costs

The same job with a risk register: wet weather on the pour, late rebar, a slow answer to the RFI, a failed inspection. Each run samples every duration, rolls every risk, and walks the graph five times: once with every risk, and once with each one left out. The gap at P80 is what that risk costs.

Sprout's spork works a run out ahead into one kernel of plain number maths, then runs it for every input at once on WebAssembly SIMD. A million runs take about a second, and this page runs them off the main thread, so it never stalls.

06ace-ledger.sp

   
Every step, written down

   
Here the atoms live in SQLite, in three tables: the atoms, the links between them, and the events. Done is still derived in Sprout, from the rows, and every closure goes into the event log with the day it happened.

   
Each run is one day on site: the first workable atom closes and the log grows by a line. The database is kept in this browser, so the job carries on where you left it.

07ace-site.sp

   
Positions are expressions, rules are constraints

   
Nothing on this plan stores a position. Each building's place is an expression over a few named dimensions: the turbine hall sits at the reactor's edge plus the width of the road, and the service building sits below the reactor the same way. Change the reactor and everything that depends on it moves.

   
Every rule is a constraint with a name. Must not rules are clashes, two things on the same ground. Must rules are limits the design has to meet. The panel under the plan shows each one holding or failing as you go.

08ace-morning.sp

   
The morning question

   
Status meetings ask what happened. The job moves on a different question: which constraints, killed today, release the most work? For each open constraint, ACE counts the hours of work that would become workable if it cleared this morning, and ranks them.

   
Some constraints release nothing on their own, because the work behind them needs a second one too. The program finds the partner each one needs.
